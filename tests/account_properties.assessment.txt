NAMED-ACCOUNT DISCOVERY (local/private; no public disclosure)

Plan and oracle
---------------
Target the named-user branch separately from HOME/current-user path parsing.
Use getpwnam_r/getpwuid_r with caller-owned storage rather than production
getpwnam; inventory local accounts through dscl on Darwin (getent elsewhere).
Cross account classes with six public AsRef<Path> representations and suffixes.
Use a deterministic root regression to calibrate the oracle, then generated
account choices, unknown names, and histories interspersed with foreign libc
lookups. Keep opt-in cross-thread stress separate from ordinary tests.

Platform contract and prospective minimal repair
------------------------------------------------
Darwin SDK getpwent/getpwnam manual, lines 141-149:
  /Library/Developer/CommandLineTools/SDKs/MacOSX.sdk/usr/share/man/man3/getpwent.3
The lookup functions are thread-safe with thread-specific storage, invalidated
by subsequent calls on that thread. The manual explicitly calls them unsuitable
for libraries/frameworks because they invalidate the application's prior data.
Apple primary-source online manual:
  https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man3/getpwnam.3.html
Linux man-pages primary contract:
  https://man7.org/linux/man-pages/man3/getpwnam.3.html
getpwnam is MT-Unsafe race:pwnam locale; returned storage may be overwritten by
later getpwnam/getpwuid/getpwent calls. Reentrant variants are MT-Safe locale and
write records/strings into caller-owned storage. _SC_GETPW_R_SIZE_MAX is an
initial suggestion, not a bound; ERANGE requires a larger buffer.

Consequently Linux shared-storage use is an inspection/contract-based safety
risk, NOT an observed Linux race or demonstrated exploit in this investigation.
Darwin's passing stress does not validate Linux. No foreign pointer was read
after a later non-reentrant call; no stale-pointer UB witness was manufactured.
No Linux runtime was available (parent found Docker client but no daemon).

Prospective minimal repair: replace getpwnam with getpwnam_r, retain caller-owned
passwd and a growable buffer through the pw_dir copy, handle ERANGE using checked
growth, inspect return status and result before dereferencing, and preserve
existing invalid-NUL/not-found/missing-home errors. Choosing how to expose
non-lookup OS errors needs care because today's public error enum has no
system-lookup-error variant. A crate-only mutex is insufficient: unrelated
foreign callers do not take that mutex. No production fix was made here.

Blindspots
----------
No existing Unicode-named account was provisioned. No live account database
mutation, remote directory backend failure, giant record, ERANGE injection,
null pw_dir fixture, locale mutation, allocator failure, or race detector run.
Inventory can omit remote accounts; fallback names cover only a small set if
dscl/getent is unavailable. Oracle expects successful OS queries and does not
silently reinterpret OS errors as absent accounts. Stress is nondeterministic
and cannot establish absence of races or other memory-safety violations.
